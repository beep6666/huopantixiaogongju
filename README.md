# 货盘经营决策助手 · 最小可运行实验

这不是 AI 自动经营平台，也不是统一经营中台。

它验证一个更小的问题：

> 系统自动校验、关联并整理任务级决策资料，是否能减少货盘负责人找数、拼表、核对与追问的成本，同时不增加关键遗漏？

产品边界：

`经营目标 → 系统准备事实/未知/冲突 → 人形成策略 → 系统生成执行清单 → 描述性结果回收`

## 已实现

- 创建经营任务：目标、区域、门店范围、周期、Owner、新品/清货约束；
- 导入五类 UTF-8 CSV/JSON，或整包工作区 JSON；
- 明确区分空白、Demo、真实导入和混合数据；
- 字段、类型、枚举、日期、复合主键、时效、稳定 ID 和引用完整性校验；
- 决策资料包：
  - 商品销量、透明趋势、库存、生命周期和渠道覆盖；
  - 商品 × 小程序/团购/外卖等渠道矩阵；
  - 停售、低库存、区域、未上线、新品保护、清货、项目锁位；
  - 可调/锁定资源位和明确的渠道空白；
  - 数据缺失、过期、未知与关联错误；
- 人工填写商品、渠道、资源位、动作、判断依据；
- 自动转换为可编辑 Owner/Deadline/状态的执行清单并导出 CSV；
- 整体、动作商品、其他商品的基础前后对比；
- 固定非因果声明；
- 记录原流程/MVP 准备时间、额外查询、追问和复用意愿；
- 导出完整工作区 JSON；
- 纯逻辑自动测试。

## 启动

需要 Node.js 18+。项目没有第三方运行依赖，不需要 `npm install`。

```powershell
git clone https://github.com/beep6666/huopantixiaogongju.git
cd huopantixiaogongju
npm start
```

打开：

```text
http://127.0.0.1:4173
```

停止服务：在终端按 `Ctrl+C`。

运行测试：

```powershell
npm test
```

## 如何加载 Demo

1. 启动页面。
2. 点击顶部或数据装载页的“加载 Demo”。
3. 页面会显示“演示模式”，所有商品、销量、库存、项目和规则均为虚构。
4. 进入“装载决策数据”，确认 5/5 数据集已加载。
5. 点击“生成决策资料包”。

Demo 不会自动生成策略或经营结论，也不会伪造已验证结果。

## 如何导入真实数据

### 方式一：每类单独导入

在“装载决策数据”页：

1. 分别点击五个卡片的“下载空模板”；
2. 将 Excel 另存为“CSV UTF-8”，按模板填写；
3. 逐类选择 CSV/JSON；
4. 查看数据质量报告；
5. 修复所有错误后重新导入；
6. 提醒可以带入资料包，但必须由负责人判断是否能继续。

仓库中的空模板：

- `data/templates/product_performance.csv`
- `data/templates/product_channel_states.csv`
- `data/templates/resource_slots.csv`
- `data/templates/business_projects.csv`
- `data/templates/business_rules.csv`

### 方式二：导入整包 JSON

顶部点击“导入工作区 JSON”。支持：

```json
{
  "task": {},
  "data": {
    "product_performance": [],
    "product_channel_states": [],
    "resource_slots": [],
    "business_projects": [],
    "business_rules": []
  }
}
```

也可以导入此前从本工具导出的完整工作区 JSON。

### 关键格式约定

- 所有表使用稳定 ID，尤其是 `product_id`；不按名称模糊匹配。
- 日期：`YYYY-MM-DD`。
- 时间：ISO-8601，例如 `2026-10-18T08:00:00+08:00`。
- 多值：用 `|` 分隔，例如 `华东|华南`。
- 数字：只写数字，不写 `12%`、`1 万` 或货币符号。
- 缺失、0、false、offline 和 unknown 必须区分。
- 五类输入都建议带 `snapshot_at`。

完整 schema 和枚举见 [docs/mvp-experiment.md](docs/mvp-experiment.md)。

## 如何完整走一遍经营任务

### 1. 创建任务

在“创建经营任务”填写：

- 目标：华东门店未来 7 天整体销量 +8%；
- 范围：华东 120 家门店；
- 周期与 Owner；
- 勾选保护新品、存在清货任务。

保存后进入数据装载。

### 2. 装载与校验数据

导入五类文件或加载 Demo。先看“数据质量与关联报告”：

- 错误会阻止生成资料包；
- 提醒会保留在资料包首屏；
- 未上传不是“没有”；
- 未知商品引用和重复主键不会被静默修正。

### 3. 生成决策资料包

点击“生成决策资料包”，按顺序查看：

1. 资料是否可信；
2. 当前值得查看的商品事实；
3. 商品 × 渠道矩阵；
4. 规则与项目冲突；
5. 可调、锁定资源位和渠道空白。

“值得查看”不是系统推荐，没有综合分。

### 4. 人工形成策略

负责人点击“新增动作”，自己填写：

- 商品；
- 渠道；
- 资源位（可选）；
- 动作；
- 判断依据；
- 建议 Owner 和 Deadline。

选择停售商品、区域不适用商品或锁定资源位时会显示冲突。系统不会预填策略。

Demo 中可以用以下非真实示例走通：

- 商品：`翅根桶 · SKU-001`
- 渠道：`小程序 · miniapp`
- 资源位：`首页商品坑位 1`
- 动作：`保持当前商品并强化一周展示`
- 判断依据：`近 7 日销量上升、库存充足，资源位快照为可调整`

### 5. 生成执行清单

点击“生成执行清单”：

- 系统只生成任务文字；
- 人补齐 Owner、Deadline；
- 状态可更新为待执行、进行中、已完成、已取消；
- 点击“导出执行清单 CSV”进入现有协作方式。

### 6. 回收结果与实验反馈

录入相同口径的：

- 门店整体销量前/后；
- 动作涉及商品前/后；
- 其他商品前/后。

页面只计算描述性变化率，不声称因果。

更重要的是填写：

- 原流程资料准备分钟数；
- 使用 MVP 后的分钟数；
- 仍需打开的系统/表格数；
- 仍需追问次数；
- 未匹配记录数；
- 下次是否愿意继续用；
- 最影响判断的缺失信息。

最后点击“导出完整实验记录”，保存工作区 JSON 用于复盘。

## 如何判断第一轮是否值得继续

建议在实验前与业务共同确认门槛：

- 资料准备人工时间相对基线下降至少 30%；
- 策略涉及商品 ID 关联 100%；
- 关键阻断漏报 0；
- 静默丢行 0；
- “未知”被误显示为“无/否” 0；
- 资料包后仍需额外查询显著下降。

至少跑 3 个真实任务再判断是否扩展。第一单建议 shadow 模式。

## 数据存在哪里

- 页面数据保存在当前浏览器 `localStorage`；
- 不自动上传任何业务文件；
- 清除站点数据或点击“清空本地数据”会删除；
- 工作区 JSON 包含源数据和人工判断，需按业务数据安全要求保存；
- 当前没有账号、权限、审计、加密或多人协作，不适合直接作为生产系统。

## 原页面与本版本的关系

本轮没有覆盖用户提供的两个原始 HTML。

- `货盘决策助手·轻量版(1).html` 被用作交互基线；
- `需求共创与愿景看板 (2).html` 被用作问题信号与远期愿景参考；
- 新实现修正了原版的名称关联、硬编码冲突、硬编码效果、不可编辑责任信息、重复 DOM ID 和流程状态问题；
- 远期“货盘中枢”没有进入本轮架构。

## 当前最重要的未验证项

1. 五类真实数据能否在同一时点取得；
2. 不同来源能否使用同一个稳定 `product_id`；
3. “华东 120 店”能否在各来源复现同一门店集合；
4. 7 类规则模板能覆盖多少真实约束；
5. 导入/清洗模板的时间是否抵消自动整理节省的时间；
6. 可操作空间能否在 7 天窗口内真正执行。

这些未知不是缺陷列表的尾声，而是下一轮产品决策的输入。
