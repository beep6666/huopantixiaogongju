# 最薄可运行实验

## 0. 唯一核心命题

> 在不替货盘负责人做经营判断的前提下，把若干来源的任务级快照自动校验、关联、整理成可追溯的决策资料包，能否显著减少“找数—拼表—核对—追问”的人工时间，并且不增加关键事实漏报/错报？

本轮不以“7 天销量是否提升”判定 MVP 成败。销量受策略质量、执行、季节、活动等共同影响，只作为描述性结果回收。

## 1. 一次实验需要哪些输入

### 经营任务：页面表单

| 字段 | 是否必须 | 用途 |
|---|---:|---|
| 任务名称、目标原话 | 是 | 保留业务问题，不自动转成策略 |
| 目标指标、目标变化 | 指标必须，变化可空 | 供负责人理解，不参与推荐 |
| 区域、门店范围说明 | 是 | 约束商品、项目和结果口径 |
| 开始/结束日期 | 是 | 判断项目重叠与结果窗口 |
| Owner | 是 | 明确最终经营判断责任人 |
| 保护新品、存在清货任务 | 否 | 触发相关提醒 |
| 已知约束与备注 | 否 | 记录目前无法结构化的上下文 |

### 五类文件输入

系统支持每类一份 UTF-8 CSV/JSON，也支持一个工作区 JSON。空模板位于 `data/templates/`，页面可直接下载。

#### A. 商品表现（必须）

文件：`product_performance.csv`

最小必填：

- `product_id`、`product_name`
- `lifecycle`: `new / regular / clearance / phase_out`
- `status`: `active / stopped / out_of_stock`
- `sales_7d`、`sales_prev_7d`
- `stock_qty`
- `supply_status`: `normal / tight / stopped`
- `allowed_regions`：多值用 `|` 分隔，例如 `华东|华南`；全国写 `全国`
- `snapshot_at`：ISO-8601 时间

暂不要求门店 × 商品 × 日明细；第一轮只验证任务范围内的汇总能否支持判断。

#### B. 商品 × 渠道状态（必须）

文件：`product_channel_states.csv`

最小必填：

- `product_id`、`channel_id`、`channel_name`
- `listing_status`: `online / offline / pending / paused`
- `snapshot_at`

可选：`assortment_name`、`price`、`sales_7d`。

主键是 `product_id + channel_id`。没有记录显示“未知”，不会自动解释为未上线。

#### C. 资源位快照（必须）

文件：`resource_slots.csv`

最小必填：

- `slot_id`、`slot_name`
- `channel_id`、`channel_name`
- `region`
- `adjustability`: `adjustable / locked / unavailable`
- `snapshot_at`

可选：当前商品、锁定原因、最早可调时间、曝光/点击/转化、Owner。资源位历史效率不是核心实验的必要条件。

#### D. 当前业务项目（实验强烈建议，代码允许缺失）

文件：`business_projects.csv`

最小必填：

- `project_id`、`project_name`
- `project_type`: `launch / clearance / marketing / regional`
- `region`、`start_date`、`end_date`
- `locks_resource`: `true / false`
- `snapshot_at`

关联商品、渠道、资源位 ID 均使用 `|` 分隔。若没有当前项目，应上传只有表头的文件表示“已确认 0 行”；完全未上传表示未知，会保留提醒。

#### E. 业务规则（实验强烈建议，代码允许缺失）

文件：`business_rules.csv`

首轮只支持：

| `rule_type` | 含义 | `parameter` |
|---|---|---|
| `STOP_SALE` | 停售/待下架不可用于动作 | 空 |
| `LOW_STOCK` | 低于库存阈值提示 | 数字阈值 |
| `REGION_SCOPE` | 商品区域不包含任务区域 | 空 |
| `CHANNEL_OFFLINE` | 渠道状态不是 online | 空 |
| `PROJECT_LOCK` | 当前项目在任务期锁定资源位 | 空 |
| `NEW_PRODUCT_PROTECTION` | 任务声明保护新品 | 空 |
| `CLEARANCE_VISIBILITY` | 清货商品/项目显式展示 | 空 |

每条还需 `rule_id`、`rule_name`、`severity(block/warn/info)`、`enabled`、`owner`、`snapshot_at`；有效期可选。

无法放进这些模板的口头规则，首轮应写入任务备注和待确认清单，而不是扩展通用表达式引擎。

## 2. 哪些数据是必须的

代码层面阻塞资料包生成的条件：

1. 经营任务完整；
2. 商品表现已加载且非空；
3. 商品 × 渠道状态已加载且非空；
4. 资源位快照已加载且非空；
5. 必填字段、类型、枚举、日期和主键通过；
6. 所有商品引用都能通过稳定 `product_id` 关联。

真实实验层面，业务项目和业务规则也应由 Owner 提供或明确确认为空。代码允许带提醒继续，是为了让“规则拿不到”本身成为实验发现，而不是把产品卡死在演示阶段。

## 3. 哪些数据暂时可以不要

- 销量预测、推荐得分、AI 策略；
- 门店 × 商品 × 日明细；
- 资源位完整历史中心；
- 供应计划、顾客标签、竞品数据；
- 完整毛利模型；
- 实时 API、数据仓库和统一主数据平台；
- 组织权限、审批流、消息通知；
- 通用规则 DSL；
- 因果推断和增量归因。

如果真实负责人明确表示缺少某项就无法做判断，应记录额外查询次数和分钟数，再决定第二轮是否加入。

## 4. 输入数据格式约定

1. CSV 使用 UTF-8；从 Excel 另存为“CSV UTF-8”。第一轮不直接兼容多 Sheet、合并单元格和展示格式。
2. 日期用 `YYYY-MM-DD`；时间用 ISO-8601，例如 `2026-10-18T08:00:00+08:00`。
3. 多值用 `|` 分隔。
4. 数字列只写数字，不写 `12%`、`1 万` 或货币符号。
5. 0、空值、否、未上线、未知必须分别表达。
6. 每份快照必须带 `snapshot_at`；文件导入时另外记录来源文件名和 `imported_at`。
7. 商品、渠道、资源位、项目和规则都使用稳定 ID。系统不按名称模糊匹配。

JSON 单数据集可以是数组，也可以是 `{ "product_performance": [...] }`；整包可以是：

```json
{
  "task": {},
  "data": {
    "product_performance": [],
    "product_channel_states": [],
    "resource_slots": [],
    "business_projects": [],
    "business_rules": []
  }
}
```

## 5. 系统需要做哪些处理

1. **导入校验**：必填列、类型、枚举、日期、复合主键重复、快照新鲜度。
2. **引用完整性**：按稳定 ID 关联；未知商品、未知资源位和名称冲突逐条展示。
3. **数据清单**：区分未上传、已加载 0 行、Demo、真实导入和混合数据。
4. **机械派生**：本 7 日相对前 7 日变化率、渠道覆盖、未上线状态、资源位可调/锁定。
5. **有限规则评估**：只执行上表 7 类模板，并展示 rule、证据和来源。
6. **项目冲突**：只判断项目周期/区域是否与任务重叠、是否锁定明确资源位。
7. **生成资料包**：数据健康、商品事实、跨渠道矩阵、限制/冲突、可操作空间和未知项。
8. **策略校验**：提示所选商品/渠道/资源位的已知冲突；不替人生成策略。
9. **清单转换**：一条人工策略生成一条执行任务骨架；Owner/Deadline 由人补齐。
10. **结果计算**：整体、动作商品、其他商品的前后差值/变化率；固定显示非因果声明。

## 6. 系统最终输出什么

- 资料包生成时间与数据模式；
- 数据健康/未知项总览；
- 商品事实表：销量、透明趋势、库存、生命周期、渠道覆盖、规则状态；
- 商品 × 渠道矩阵：在线、离线、待上线、暂停、未知；
- 可追溯的规则/项目/资源位冲突；
- 明确的可调资源位、锁定资源位、未上线渠道状态；
- 人工策略动作与判断依据；
- 可编辑并可导出 CSV 的执行清单；
- 描述性前后结果；
- 实验反馈：原流程/MVP 时间、额外查询、追问、未匹配、复用意愿；
- 可导出的完整工作区 JSON。

## 7. 人在哪一步进行判断

1. 确认目标、范围、窗口和可比口径。
2. 判断数据质量提醒是否可接受，是否需要返回补数据。
3. 确认 ID 映射；当前没有映射 UI，真实输入若没有统一 ID 则实验暂停。
4. 选择商品、渠道、资源位和动作，填写依据。
5. 对规则提醒或例外作人工取舍；硬阻断不能被静默绕过。
6. 补齐 Owner/Deadline，决定如何进入现有协作流程。
7. 解释结果变化，并决定是否继续/停止/放大；系统不作因果结论。

## 8. 一次真实实验怎么跑

### 实验准备

- 选一个真实区域 7 日任务；第一单建议 shadow 模式，不直接影响经营。
- 限定 20–100 个候选 SKU、3 个渠道和当期资源位。
- 指定货盘负责人、五类数据 Owner、计时观察人。
- 预先确定指标口径和关键阻断 gold list。

### 执行流程

1. 回放一个可比的既有任务，记录从任务下达到资料可用的总耗时；拆成等待、导出、清洗、匹配、追问、真正判断。
2. 同一时点导出五类快照，记录来源和 Owner。
3. 在 MVP 创建任务并上传文件；计时“原始文件到齐后”的人工操作时间，同时另记等待时间。
4. 处理阻塞错误；记录所有补字段、映射、返工和追问。
5. 生成资料包，负责人抽查至少 5 个商品和全部阻断项，并与源表核对。
6. 负责人填写 2–5 个策略动作及依据。
7. 生成执行清单，补齐 Owner/Deadline，导出 CSV 或进入现场流程。
8. 7 天后录入相同口径前后结果。
9. 填写实验反馈，决定下一轮是补数据、删字段、改模板，还是停止扩展。

单次可以发现阻塞；价值判断建议至少运行 3 个真实任务。

## 9. 如何判断 MVP 有没有价值

### 主指标

| 指标 | 计算 | 建议门槛（实验前共同确认） |
|---|---|---|
| 资料准备人工时间 | 原始文件到齐 → 资料包被认可的实际操作分钟数 | 相对基线下降至少 30% |
| 端到端准备时间 | 任务下达 → 资料包认可 | 拆开等待和人工时间，找出真正瓶颈 |
| 额外查询成本 | 资料包后仍需打开的系统/表格数、询问人数和分钟数 | 相对基线下降至少 50%，或每单不超过 2 次 |

### 可靠性护栏

- 策略涉及商品 ID 关联必须 100%；整体建议至少 95%。
- 未匹配记录 100% 可见，静默丢行 0。
- 关键阻断漏报 0。
- “未知”误显示为“无/否”的次数为 0。
- 关键字段完整率和时效合格率建议至少 95%。

### 使用信号

- 策略动作是否引用了资料包中的事实；
- 执行清单生成后被修改/新增多少任务，以及为什么；
- 负责人“下次是否愿意用”；
- 仍缺哪些信息、是否每次都不同。

### 不作为本轮成败指标

- 7 天销量是否达到 +8%；
- 动作商品涨幅；
- 系统是否给出了“正确推荐”。

这些可以观察，但不能代替资料准备成本和可靠性，也不能被解释为因果。

## 10. 预先定义的 Pivot 信号

- 若超过一半时间花在找数据 Owner/等待导出：下一轮先验证固定交付责任，不扩页面。
- 若商品 ID 关联低于 90%：先做身份映射审核台，不增加 AI 或规则。
- 若多数规则无法落入模板：改为上传已判定约束快照，不建通用规则引擎。
- 若负责人仍需大量群聊语境：增加“待确认问题”捕获，不让模型猜结论。
- 若资料包可靠却无人能执行：问题可能在权限/资源而非资料准备，应转向执行协调实验。
